# Frevo!（ko-ko-ya）アコースティックギター タブ譜

`outputs/target/best/acoustic_guitar.wav`（Champion パイプラインで抽出したギター stem）から自動採譜したギターのタブ譜です。
作曲は笹子重治、原曲の録音は 2011 年。

> **注意**：自動採譜です。耳で聴いて原曲と照合する確認はまだ行っていません。
> 正解の分かっている曲での再現実験では、分離した音から採譜した場合、検出した音の約 7 % が誤りで、実際に鳴っている音の約 12 % を取りこぼしました（下の「精度の実測」。数値がやや楽観的な可能性についての注意も参照）。
> 確認用に、元のギターとタブを音にしたものを聴き比べられるチェッカー（`check/index.html`）を用意しています。

## 耳での確かめ方

`check/index.html` をブラウザで開きます（`check/` の MP3 と同じフォルダに置いたまま）。

- 再生すると、いま鳴っている 16 分音符がタブ上で黄色く光ります。
- 「元のギター」「タブの合成音」「左右比較（左＝元、右＝タブ）」を再生位置を保ったまま切り替えられます。
- 速さを 50〜85 % に落としても音程は変わりません。
- 小節番号をクリックでその小節へ。小節ループ（L キー）、Shift＋クリックでループ範囲を拡大。
- **赤（!!）・オレンジ（!）の小節番号** は自動チェックで要確認になった小節です（70 小節、うち理由が 2 つ以上の優先 20 小節）。マウスを乗せると理由が出ます。「次の要確認小節」ボタンで順に回れます。
- **赤い波線のフレット番号** は、3 つの採譜モデルのうち 1 つしか検出しなかった音です（79 音）。再現実験ではこの種の音の約半分（43 音中 20 音）が誤りだったので、まずここを聴くのが効率的です。

違う音が見つかったら、小節番号と内容を教えてもらえれば直します。

## 読み方

- **チューニング**：レギュラー（E A D G B E）。録音は A4 ≒ 442 Hz（+9 cent）。
- **拍子・テンポ**：2/4、♩ ≒ 156。16 分音符はブラジル音楽特有の「訛り」（2 つ目の 16 分がやや遅く、4 つ目がやや早い）で演奏されていますが、譜面は通常の 16 分で書いています。
- **小節番号**：ギターが入る 0:03.3 を 1 小節目としています（それ以前のイントロはギター休み）。各小節に録音内の時刻を併記。
- **奏法**：親指のベース（多くの小節で拍頭に、ルートと 5 度を交互に）と、裏拍・16 分裏に入るコードの刻みが基本形です。
- **コード名**：採譜したノートから推定したもので、参考表示です。
- **曲の流れ**：A テーマ（Gm7–C7(9)… F7–E7–E♭7–D7 の半音下降ドミナント）が小節 1・17・33・65・117・129 付近に現れ、81 小節目から音の少ない対照部、143 小節目付近から C♯7 を経て F♯ へ転調するコーダに入り、F♯6(9) のトレモロで終わります。

## 採譜方法

1. **チューニング推定**：スペクトルピークの周波数ヒストグラム（100 cent 周期の円周平均）で +9 cent を検出し、リサンプリングで補正。
2. **ノート検出**：高分解能オンセット／オフセット回帰 CRNN（Kong et al. 2021 のアーキテクチャを再実装）に、X. Riley 氏のギター用学習済み重み（`xavriley/midi-transcription-models`、MIT）を使用。
   同じ構造の重み 4 種（kroma / GAPS / GAPS 論文版 / FL）を下の再現実験で比べ、最も正確だった **FL と GAPS 論文版の 2 つを平均（アンサンブル）** して使っています。
   `.pth` 形式の重みは、PyTorch の安全読み込み（`weights_only=True`）で数値配列の復元関数だけを許可して safetensors に変換してから使います（静的解析で、ほかに実行される要素がないことを確認済み）。
3. **ビート・小節**：親指ベースを重み付けしたギター自身のオンセット包絡でビート追跡 → 全オンセットによる最小二乗でビート時刻を補正 → 16 分の訛り位置をクラスタリングして量子化 → 和声変化とベース位置から小節頭を決定。
4. **弦・フレット割り当て**：（運指 × 左手ポジション）の状態空間で Viterbi。ポジション移動・ストレッチ・鳴っている音を切らないこと等をコスト化し、GuitarSet（奏者が実際に弾いた弦の正解つきデータ）で重みを調整。構造上弾けない和音や無理なストレッチになる場合は、確信度の低い音から落とす（ベース音は優先的に残す）。
5. **コード名**：8 分単位のテンプレート照合＋ Viterbi 平滑化。
6. **書き出し**：ASCII / MusicXML / Guitar Pro 5 / LilyPond→PDF / MIDI / CSV、確認用の合成音とチェッカー。

## 精度の実測（正解の分かっている曲での再現実験）

ギターの正解（どの音をいつ弾いたか、GuitarSet は弦も）が分かっている録音を使い、この曲と同じ条件を再現して採譜精度を測りました（`scripts/bench_tab.py`、詳細は [`reports/tab_benchmark.md`](../../../reports/tab_benchmark.md)）。

- 素材：GuitarSet のボサノヴァ伴奏 4 人分（スチール弦、弦の正解つき）と、GAPS のクラシックギター（ナイロン弦）から「Tico Tico no Fubá」（ショーロ、2/4）と「Gavota Choro」。計 129 秒・917 音。
- 実在のヴァイオリンとクラリネット（URMP）と打楽器を、この曲と同じ音量比（ギターが他より約 4.7 dB 小さい）で混ぜ、この曲と同じ Champion 分離（`--quality max`）でギターを取り出してから採譜しました。
- 判定は、発音時刻が 50 ms 以内で音高が一致すれば正解（mir_eval）。

| 使ったモデル | 条件 | 適合率（出した音が正しい割合） | 再現率（実際の音を拾えた割合） | F1 | 弦の一致率 |
|---|---|---|---|---|---|
| 旧版（kroma） | 分離した音から | 0.928 | 0.790 | 0.853 | 0.781 |
| **現在（FL＋GAPS 論文版）** | **分離した音から** | **0.930** | **0.880** | **0.904** | 0.771 |
| 現在 | 　うちボサノヴァ伴奏 | 0.923 | 0.872 | 0.897 | 0.771 |
| 現在 | 　うちショーロ等（ナイロン弦） | 0.946 | 0.900 | 0.922 | – |
| 現在 | 分離前のきれいなギター | 0.944 | 0.908 | 0.926 | 0.774 |

- 旧版のモデルは、伴奏の和音の音を約 2 割取りこぼしていました。現在のアンサンブルは適合率を保ったまま、その多くを拾えています。
- 別の確認として、分離前のきれいな GuitarSet 60 抜粋（全奏者・全スタイル）でも F1 は旧版 0.798 → 現在 0.913 でした（[`reports/tab_benchmark_guitarset.md`](../../../reports/tab_benchmark_guitarset.md)）。
- モデル単体との比較（分離した音から、F1）：旧版 0.853、FL 単体 0.883、GAPS 論文版単体 0.902、2 つの平均（現在）0.904。学習データと重ならないショーロ等の部分（270 音）では、旧版 0.914、FL 単体 0.893、GAPS 論文版単体 0.908、現在 0.922 で、2 つの平均がどちらの単体よりも良くなりました。
- **注意（学習データの重なり）**：GAPS 論文版モデルは、GAPS の論文が「GuitarSet で学習した設定」の結果も報告しており、公開されている重みがどちらか明記されていません。そのため **GuitarSet を使った数値（伴奏の行・上の 60 抜粋）は、GAPS 論文版を含むものが楽観的な可能性があります**。どのモデルの学習にも使われていない GAPS テスト曲（ショーロ等の行）では、旧版 0.914 → 現在 0.922 と改善は小さめです（270 音中、拾えた音が 4 音増えた程度の差です）。なお GuitarSet で学習していないと明記された FL モデル単体でも、伴奏の取りこぼしは大きく減ります（GuitarSet 60 抜粋で F1 0.798 → 0.896）。
- 分離による精度の低下は F1 で約 0.02 でした（0.926 → 0.904）。
- 弦の一致率は「正しく拾えた音のうち、奏者と同じ弦を選んだ割合」です（同じ音を別の弦で弾く押さえ方もあるため、残りが必ずしも弾けない形というわけではありません）。
- **この曲への当てはめ（目安）**：再現実験で、タブの音が正しかった割合は、3 つの採譜モデル（下の「自動チェック」）が全部検出した音で 96 %、2 つで 84 %、1 つだけで 53 % でした。これをこのタブの内訳（1070 音 / 107 音 / 79 音）に当てはめると、このタブ（1256 音）の**誤った音はおよそ 90 音（70〜110 音）**です。抜けている音は、再現率 0.88 から**およそ 130〜190 音**と見込まれます。ただし上の学習データの重なりの可能性と、演奏スタイルや録音が再現実験と違うことから、実際はこれより多いこともあり得ます。

## この曲での自動チェック（正解がないため状況証拠）

正解譜がないため、以下は矛盾がないかの確認です（`scripts/verify_tab.py`、結果は [`verification.md`](verification.md)）。旧版（kroma のみ）からの変化も並べます。

| チェック | 旧版 | 現在 |
|---|---|---|
| 独立した別の採譜 AI（Spotify の Basic Pitch）との一致（onset F1 / 音名のみ） | 0.64 / 0.66 | **0.67 / 0.69** |
| 元のギターとタブを音にしたものの和音の響きの一致（クロマ、小節ごとの中央値） | 0.87 | **0.88**（0.7 未満の小節なし） |
| 強く鳴っているのにタブに無い音（80 ms 以上） | 20 箇所 | **10 箇所** |
| 繰り返し部分の一致度（同じ箇所の小節どうし、平均） | 0.551 | **0.582** |
| 繰り返しの一方にだけ無く、そこでも音が検出される | 21 | **8** |
| 3 つの異なるギター採譜モデルのうち何個が検出したか（タブの音） | – | 3 個：1070 音、2 個：107 音、1 個：79 音 |
| 2 つ以上のモデルが聞き取ったがタブに無い音 | – | 34 |
| 演奏可能性 | 最大ストレッチ 4、最高 10 フレット | 最大ストレッチ 4、最高 7 フレット、5 フレット超の跳躍なし |

- 旧版で使っていた kroma は GAPS モデルと出力が完全に一致（相関 1.000）したため、1 つとして数えています。
- 繰り返し部分の一致度は、同じ奏者が同じ箇所を同じように弾くという前提での間接的な指標です。
- 1 つのモデルしか検出しなかった 79 音と、複数モデルが聞き取ったのにタブに無い 34 音などは、`review.json` とチェッカーの「要確認」に入っています。
- それぞれの当たりやすさを再現実験で同じ規則で測ると、1 つのモデルしか検出しなかった音は 43 音中 23 音が正しく（約半分が誤り）、「2 つ以上のモデルが聞き取ったがタブに無い」音で本当に抜けていたのは 6 件中 2 件でした（件数が少ないので目安）。誤りを探すなら前者（チェッカーの赤い波線）が優先です（[`reports/tab_benchmark.md`](../../../reports/tab_benchmark.md) の後半）。

## 限界・注意点

- **自動採譜で、耳での照合は未実施**です。上の見込みどおりなら、タブの音の 1 割弱が誤りで、実際に鳴っている音の 1 割強が抜けています（これより多い可能性もあります）。
- 弦・フレットは「音高を満たす自然な押さえ方」の推定で、奏者（笹子重治氏）の実際の運指と同じとは限りません。
- コード名はノートからの推定で、参考表示です。
- 分離 stem 由来のため、ヴァイオリン・クラリネットの漏れがわずかに残ります（タブの音のうち残差側にも同じ音があるのは約 2 %）。
- エンディングのトレモロは 16 分の刻みとして書いています。
- 16 分の訛りの強い箇所では、2 つ目と 3 つ目の 16 分の境目付近の音の位置がずれている可能性があります。

## 再現

```bash
uv sync --extra cpu --extra tab
uv run --no-sync python scripts/transcribe_tab.py --models fl gaps_paper   # 本ディレクトリを再生成
uv run --no-sync python scripts/verify_tab.py                              # 自動チェックと要確認リスト
uv run --no-sync python scripts/make_tab_check.py                          # 合成音とチェッカー
# 再現実験（データ取得・分離に CPU で約 1.5 時間）
uv run --no-sync python scripts/bench_tab.py build
uv run --no-sync python -m acoustic_separator --input data/bench_tab/mix.wav --quality max --output data/bench_tab/sep
uv run --no-sync python scripts/bench_tab.py eval        # 旧版・各モデル単体・現在のアンサンブルを比較
uv run --no-sync python scripts/bench_tab.py guitarset   # きれいな GuitarSet 60 抜粋での比較
```
